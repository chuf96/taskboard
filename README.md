# Task Board

Минималистичная доска задач, которая работает у вас на компьютере без интернета и хранит задачи в обычных `.md`-файлах.

С версии 2.0 доска — это список: каждый проект — сворачиваемая группа, каждая задача — одна строка (звезда фокуса · статус · название · тэг · исполнитель · срок). Все поля строки кликабельные и меняются прямо в строке. Наверху — группа «В фокусе сегодня». С версии 2.2 доска оформлена в стиле Notion: белый фон, шрифт Inter, синий акцент, пастельные тэги и кружок с буквой у исполнителя.

С версии 3.0 внизу две вкладки, как листы в Excel: **Tasks** (список задач) и **RoadMap** (дорожная карта с контрольными точками, связями, сдвигами и плановыми релизами). У задач появился срок.

## Запуск

1. Распакуйте архив в удобное место, например в `~/Applications/taskboard`.
2. Дважды щёлкните по файлу **«Запустить борд.command»**.
   При первом запуске macOS может сказать, что приложение от неустановленного разработчика. Тогда щёлкните по файлу правой кнопкой, выберите **«Открыть»** и подтвердите.
3. Откроется браузер с адресом `http://127.0.0.1:4317`. Выберите папку с задачами. Для пробы подойдёт «Пример доски» из архива.

Окно терминала, которое открылось вместе с бордом, — это сам борд. Пока оно открыто, доска работает. Закройте его, чтобы остановить борд.
В следующий раз последняя папка откроется сама.

**Обновление.** Распакуйте новую версию и запустите её «Запустить борд.command». Если старая версия ещё работает, новая сама её остановит и займёт её место. Номер версии виден в меню ☰, последним пунктом.

Если хотите запускать из терминала: `node server.mjs` или `node server.mjs ~/путь/к/папке`.

## Как устроена папка

```
Моя доска/
├── Работа.md            ← проект = группа задач (+ раздел «## RoadMap» с контрольными точками)
├── Ремонт.md
├── _исполнители.md      ← справочник исполнителей («- Имя», группы — «## Риски»)
├── _тэги.md             ← справочник тэгов (строки «- тэг [цвет:: зелёный]»)
├── _префиксы.md         ← коды этапов для RoadMap («- BA [название:: Бизнес-аналитика] [цвет:: голубой]»)
├── _релизы.md           ← плановые релизы на RoadMap («- 2026-11-10 [релиз:: 2.3]»)
├── _статистика.md       ← статистика по дням: всего, создано, закрыто
├── _board.json          ← порядок проектов
├── logs/2026-09-25.md   ← журнал действий, один файл на день
└── архив/
    ├── задачи/Работа.md ← удалённые и архивированные задачи
    └── проекты/…        ← архивированные проекты
```

Файлы, имя которых начинается с `_`, проектами не считаются.

## Формат задачи

```markdown
- [/] Выбрать плитку [исполнитель:: Анна] [срок:: 2026-10-30] [создана:: 2026-09-20] [взята:: 2026-09-22] ^t0042
    Комментарий — строки с отступом под задачей.
    - [ ] Подзадачи тоже сюда
```

| В файле | Статус |
|---|---|
| `[ ]` | Новая |
| `[/]` | В работе |
| `[?]` | Ожидание ответа |
| `[x]` | Закрыто |
| `[-]` | Отменена (дата — `[отменена:: …]`; во «всего задач» не входит) |
| любой другой символ | Ошибка (статус «Ошибка» с красной точкой) |

`^t0042` в конце строки — постоянный ID задачи (блок-якорь Obsidian: на задачу можно сослаться как `[[Ремонт#^t0042]]`). Борд ставит его сам при создании задачи, а задачам без ID — при первом изменении через борд. На доске ID не показывается, он нужен журналу. Номер берётся следующий после самого большого на доске и в архиве.

**Результат при закрытии.** При переводе в «Закрыто» борд предлагает записать результат одной строкой. Это необязательно. В файле это `[результат:: …]`; у закрытой задачи его можно поправить в панели. Если задачу снова открыть, результат стирается.

Для «Ожидания ответа» есть ещё два поля: `[ждём с:: 2026-09-17]` ставится само при переводе в ожидание, `[вернуться до:: 2026-10-01]` — срок, который вы ставите вручную. При выходе из ожидания оба поля очищаются. Срок «вернуться до» не может быть раньше «ждём с»: такой срок стирается, и появляется всплывающее уведомление.

**Срок.** `[срок:: 2026-10-30]` — когда задача должна быть сделана. В колонке «Срок» он виден как «30 окт», просроченный — красным, без срока — серое «нет срока». При создании задачи Enter сразу добавляет её; чтобы указать срок, нажмите Tab после названия, введите дату и Enter. Срок меняется щелчком по колонке или в панели задачи.

**Напоминания.** У задачи в «Ожидании» в колонке «Срок» два значения: «ответ 24 окт; 13 ноя» — когда вернуться за ответом и срок самой задачи. Красным, когда «вернуться до» прошло. Если «вернуться до» не указано, а ответа ждём 3 дня или больше, там красным написано «ждём N дн.». Число дней меняется в меню ☰ → «Настройки».

**Фильтр ожиданий.** Меню ☰ → «Фильтр ожиданий» → выберите человека: на доске останутся только его задачи в «Ожидании ответа» — удобно перед звонком. Сброс — ✕ на метке в шапке или Esc.

Даты вводятся одними цифрами, точки ставятся сами (`01102026` → `01.10.2026`, год можно двумя цифрами). Даты ставятся сами: «создана» при создании, «взята» при первом переводе в работу, «закрыта» при закрытии. Если задачу снова открыть, дата закрытия стирается.

Остальной текст в файле (заголовки, заметки) борд не трогает, поэтому файлы можно параллельно править в Obsidian. Изменения появятся на доске сами.

## Работа со строкой задачи

- **☆ звезда** — поставить или снять фокус. Задачи со звездой собираются в группе «В фокусе сегодня» наверху. В файле — `[фокус:: да]`. При закрытии или отмене задача выходит из фокуса.
- **Статус, тэг, исполнитель** — щелчок открывает меню. Исполнитель выбирается в два шага: сначала группа, потом человек.
- **Название** — щелчок открывает правку прямо в строке: Enter сохраняет, Esc отменяет.
- **Срок** — у задач в «Ожидании»: щелчок по «до …» или «+ срок».
- **Значок справа** (или щелчок по пустому месту строки) открывает панель задачи: даты, результат, комментарий, удаление.
- **«+ Задача»** внизу каждого проекта добавляет задачу в этот проект. **«Закрытые: N»** раскрывает закрытые и отменённые.
- Щелчок по заголовку проекта сворачивает его, **⋯** справа — переименование и архив. Заголовок можно перетащить, чтобы поменять порядок проектов, а строку — чтобы перенести задачу.

**Ширина колонок.** Список занимает всю ширину окна: колонка с названием задачи растягивается, остальные (статус, тэг, исполнитель, срок) можно сделать шире или уже, потянув за черту справа от подписи колонки в шапке списка. Двойной щелчок по черте возвращает ширину по умолчанию, для всех колонок сразу — меню ☰ → «Ширина колонок по умолчанию». Ширины запоминаются в браузере.

Наверху: всего задач, создано и закрыто сегодня и **процент** «закрыто сегодня / создано сегодня». Если сегодня ничего не создано, вместо процента стоит «—».

## Структура исполнителей

Исполнителей можно разложить по группам (отделам, направлениям). В `_исполнители.md` группа — это заголовок второго уровня:

```markdown
# Исполнители

- Ника

## Риски
- Иван
- Петр

## Право
- Олег
```

Люди до первого заголовка — «Без группы». Старый файл без заголовков работает как раньше: все без группы, а меню исполнителя показывает людей сразу, без шага с группами. Группы ведутся в меню ☰ → «Исполнители»: у каждого человека справа кнопка группы, там же «Новая группа…»; группу можно переименовать значком ✎. Пустая группа исчезает сама.

## Тэги

Тэг объединяет задачи по смыслу: «Выбросить мусор», «Помыть посуду» и «Погулять с собакой» — разные задачи с одним тэгом «домашние дела». У задачи один тэг. В файле это `[тэг:: домашние дела]`.

Список тэгов ведётся в меню ☰ → «Тэги»: там можно добавить, переименовать (тэг поменяется во всех задачах) и удалить тэг, если он больше не стоит ни у одной задачи. Тэг задаче ставится щелчком по тэгу в строке или в панели задачи. Тэг виден пастельной заливкой, как в Notion. Цвет (14 вариантов) выбирается при создании тэга, а поменять его можно, щёлкнув по тэгу в том же окне. В файле цвет хранится так: `- домашние дела [цвет:: зелёный]`. Если цвет не указан, он подбирается по названию.

## Счётчики и статистика

Вверху доски три числа: **всего задач** (все незакрытые), **создано сегодня** и **закрыто сегодня**, и рядом процент закрытых от созданных за сегодня. Числа обновляются сразу после любого изменения, а в полночь «создано» и «закрыто» обнуляются. Задачи, перенесённые в архив, в «создано/закрыто» учитываются, удалённые — нет.

Каждый день счётчики сохраняются в `_статистика.md` — таблица «Дата | Всего | Создано | Закрыто», по строке на день. По ней можно строить графики (Excel, Numbers, Obsidian). Строка за сегодня обновляется, пока идёт день; прошедшие дни не меняются. Если борд несколько дней не запускали, эти дни восстанавливаются по датам задач.

## Журнал действий

Каждое действие записывается в `logs/ГГГГ-ММ-ДД.md` внутри папки доски: новый день — новый файл, в течение дня файл дописывается. Одна строка на событие:

```markdown
# 25.09.2026, пятница

- 14:32 · Ремонт · «Выбрать плитку» · статус: Новая → В работе [id:: t0042] [событие:: статус] [из:: new] [в:: progress]
- 14:40 · Ремонт · «Выбрать плитку» · исполнитель: — → Анна [id:: t0042] [событие:: исполнитель] [в:: Анна]
- 18:05 · Ремонт · «Выбрать плитку» · статус: В работе → Закрыто [id:: t0042] [событие:: статус] [из:: progress] [в:: closed] [результат:: Берём матовую 30×60, заказ в салоне на Ленинском]
- 18:20 · Работа · «Отчёт» · создана (вне борда) [id:: t0043] [событие:: создание] [источник:: вне борда]
- 18:21 · Работа · «Отчёт» · отменено: статус: Новая → В работе [id:: t0043] [событие:: отмена] [что:: статус]
```

- Правки, сделанные в Obsidian, тоже попадают в журнал с пометкой «(вне борда)», пока борд запущен.
- В конце строки — поля Dataview для скриптов и агентов: `id` (ID задачи), `событие` (что случилось), `из` и `в` (старое и новое значение; статусы кодами new/progress/waiting/closed, даты как ГГГГ-ММ-ДД), `источник:: вне борда` для правок из Obsidian, `что` у отмены и повтора, `результат` у закрытия.
- Результат записывается полем `[результат:: …]` в строке закрытия. Если его добавили или поправили позже — отдельной строкой «результат: …». Комментарий задачи в журнал не пишется.
- Отмена и повтор пишутся отдельными строками («отменено: …», «возвращено: …»); прошлые записи не стираются.

Журнал удобно отдавать агенту: «что было сделано вчера», «что сделано по проекту X за 2 недели», «какие решения приняты по задаче Y» — ответ ищется по дате файла, названию проекта и ID задачи; ID не меняется при переименовании и переносе.

## RoadMap

Вкладка **RoadMap** внизу экрана. Дорожки — проекты, на каждой контрольные точки (ромбы) в день их срока.

```markdown
## RoadMap

- Синяя кнопка оплаты [префикс:: BA] [владелец:: Ника] [старт:: 2026-10-13] [срок:: 2026-10-30] [первоначальный срок:: 2026-10-23] [здоровье:: есть риски] [сдвигов:: 1] [задача:: t0005] [после:: m0001] ^m0003
    Описание точки — строки с отступом.
```

- **Названия проектов** слева переносятся на несколько строк. Колонку можно расширить, потянув за её правую границу в шапке; двойной щелчок по границе возвращает ширину по умолчанию.
- **Где хранится.** Раздел `## RoadMap` в конце файла проекта. Проект появляется на карте, когда у него есть этот раздел: кнопка «+ Проект» слева или первая точка в проекте. «Убрать» у дорожки работает, когда все её точки закрыты; закрытые точки уходят в `архив/задачи/Проект.md`.
- **Новая точка.** Двойной щелчок по дню на дорожке или кнопка (+) вверху. Обязательны название, владелец (из справочника исполнителей) и срок. Префикс выбирается плашкой или кодом в начале названия: «dev Синяя кнопка» → префикс DEV.
- **Префиксы** (BA, SA, DEV, IFT, PROM по умолчанию) ведутся в меню ☰ → «Префиксы»: код, расшифровка, цвет.
- **Старт работ** — необязательная дата; от неё к ромбу идёт мягкая полоса цвета здоровья.
- **Сдвиг.** Перетащите ромб на другой день (или поменяйте срок в карточке). Любой сдвиг реального срока увеличивает счётчик и требует заново выбрать здоровье: «По плану», «Есть риски», «Есть проблема». Esc отменяет сдвиг. На полосе рисуется стрелка от первоначального срока к ромбу с числом дней: красная, если срок уехал вправо, зелёная, если влево.
- **Индикативный срок** — галочка в окне новой точки и в карточке: ромб пунктирный, сдвиги не считаются. Когда галочку снимают, текущий срок становится первоначальным.
- **Закрытие.** В карточке точки «Открыта / Закрыта». Закрытая точка серая и стоит в день закрытия, со стрелкой от первоначального срока.
- **Связи.** Потяните кружок справа от ромба к другой точке, в том числе в другом проекте. Связь серая пунктирная; оранжевая, если вторая точка стоит раньше первой. Щелчок по связи и Backspace удаляют её.
- **Точка из задачи.** В панели задачи «◆ Добавить на RoadMap» (нужны срок и исполнитель). Такая точка синхронизирована с задачей в обе стороны: срок, название, владелец, закрытие и повторное открытие. Если у задачи сдвигают срок, борд спросит здоровье точки. Отмена или удаление задачи удаляют точку и её связи; архивация задачи точку оставляет. В списке задач у таких задач стоит ◆, щелчок по нему показывает точку на карте.
- **Плановые релизы.** Щелчок по дню в шапке карты: номер релиза, колонка дня подсвечивается.
- **Масштаб** Квартал / Полгода / Год: выбранный период целиком помещается в окно. Кнопки «−» и «+» рядом делают дни мельче или крупнее (день в середине экрана остаётся на месте); выбор Квартал / Полгода / Год сбрасывает их. Карта начинается с первого дня текущего квартала и прокручивается до конца следующего года. В шапке месяцы, недели («Н43») и дни, выходные затенены, сегодня отмечено синим.
- **Имена.** По умолчанию владелец точки виден при наведении. Меню ☰ → «Отображать имена» показывает имена у всех точек (и в PDF).
- **PDF.** Меню ☰ → «Скачать PDF» на вкладке RoadMap: в PDF попадают ровно те даты, которые видны на экране, в текущем масштабе. Нажали «Квартал» — в PDF квартал; нужно больше, уменьшите масштаб кнопкой «−». Все дорожки попадают целиком. Имя файла: «RoadMap 01.10.2026-31.12.2026.pdf».
- **Журнал.** Все действия на карте пишутся в тот же журнал с полями `[раздел:: roadmap]`, `[id:: m0003]`, у сдвига ещё `[дней:: +7]` и `[здоровье:: есть риски]`. История точки видна внизу её карточки.

## Горячие клавиши

- **⌘Z** — отменить последнее действие, **⇧⌘Z** — вернуть (до 50 действий, пока открыта вкладка).
- **Esc** — закрыть панель или меню, отменить правку названия, отменить сдвиг точки в окне здоровья.
- **Backspace** на RoadMap — удалить выбранную связь.
- **Enter** в поле «+ Задача» — добавить задачу и сразу ввести следующую; **Tab** — перейти к сроку.

## Для разработчика

Node.js 18+, внешних зависимостей нет. Тесты: `npm test`.
Настройки (последняя папка и недавние) хранятся в `~/.taskboard/config.json`.
Сервер слушает только `127.0.0.1` и не обращается к сети. Шрифт Inter лежит в `public/fonts` (лицензия SIL OFL 1.1, файл лицензии рядом).
